# OpenSousVide: mobile app

A React Native (Expo) app for controlling a ChefSteps Joule over Bluetooth:
pair once, pick a temperature, start, and stop. The Joule holds the
temperature on its own, so the app only needs to be open to change settings or
watch the water temperature.

(This is an unofficial app, not affiliated with ChefSteps or Breville. The code in
this repository is provided as-is, with no warranty, etc.)

For your Android device, [download and install the APK](../release/opensousvide.apk)
(or build and install from source).

For your iOS device, I have not yet published the app on the App Store, so you
will need to build and deploy it yourself, for now. 

## Requirements

- Node.js 20+
- For Android: the Android SDK with `ANDROID_HOME` set, JDK 17-25 with
  `JAVA_HOME` set, and a physical phone with USB debugging enabled.
- For iOS: a Mac with Xcode and CocoaPods (`brew install cocoapods`), an Apple
  developer account signed in to Xcode, and a physical iPhone with Developer
  Mode on (Settings > Privacy & Security).

Emulators and the iOS Simulator have no Bluetooth, so they can't reach a Joule.

The app uses a native BLE module, so it won't run in Expo Go. It runs as a
development build of its own.

## Run on an Android phone

From this `mobile/` folder:

```sh
npm install
npx expo run:android      # builds, installs on the connected phone, starts Metro
```

After the first install you only need `npx expo start` while you're changing
JavaScript. Rebuild with `npx expo run:android` after adding native modules or
changing `app.json`.

### Windows: "mkdir ... No such file or directory" during the C++ build

Some native build paths exceed 260 characters. Enable Windows long paths
(`LongPathsEnabled` = 1 under
`HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`). Then install CMake 4.x
with the Android SDK Manager, because the default CMake 3.22.1 bundles a ninja
that ignores that setting. Point the build at it in `android/local.properties`.
Use forward slashes, since backslashes are escape characters in this file:

```properties
sdk.dir=C:/android
cmake.dir=C:/android/cmake/4.0.2
```

`npx expo prebuild --clean` deletes `android/`, so you'll need to recreate
this file afterwards.

## Run on an iPhone

From this `mobile/` folder, with the iPhone connected by USB and unlocked:

```sh
npm install
npx expo run:ios --device     # builds, installs on the iPhone, starts Metro
```

`--device` without a value lists the connected devices to pick from. You can
also pass a device name or UDID (`xcrun xctrace list devices` shows them).

- **Signing.** The build is signed with your Apple Development certificate. If
  your Mac has more than one, Expo asks which to use. If Xcode reports that
  your account already has a certificate whose private key isn't in your
  keychain, open Xcode > Settings > Accounts > Manage Certificates and create a
  new Apple Development certificate.
- **Permissions.** On first launch, allow Local Network access (the
  development build uses it to reach Metro) and Bluetooth access.
- **Dev client launcher.** If the app opens on the Expo launcher instead of the
  app, tap the Metro server listed there, or enter `http://<your Mac's IP>:8081`.

As on Android, `npx expo start` is enough while you're changing JavaScript.
Rebuild with `npx expo run:ios --device` after adding native modules or
changing `app.json`.

### A build that runs without Metro

```sh
npx expo run:ios --device --configuration Release
```

This embeds the JavaScript bundle, so the app runs on its own. It replaces the
development build in place and keeps the pairing, because both use the same
bundle ID and signing.

It's signed with a development provisioning profile, so it only installs on
devices registered to your Apple developer team, and stops launching when that
profile expires (one year for a paid account, seven days for a free one).
Rebuild before then to renew it. Sharing it with other people needs TestFlight
or Ad Hoc distribution, which this project doesn't set up.

## Metro and generated folders

To stop Metro servers left running from this project (for example after
closing a terminal on Windows, which can leave `node.exe` behind), run
`npm run stop-metro`. Add `-- --port 8082` to stop just one, or `-- --dry-run`
to only list them. It only ever stops this project's own `expo start`
processes.

The `android/` and `ios/` folders are generated by `npx expo prebuild` and are
not checked in. Configure native settings in `app.json` instead.

## Debugging in VS Code

Install Microsoft's **React Native Tools** extension
(`msjsdiag.vscode-react-native`). The repo's `.vscode/` folder already holds
the configuration:

- `settings.json` sets `react-native-tools.projectRoot` to `./mobile`, because
  the app lives in a subfolder.
- `launch.json` has **Attach to OpenSousVide (Hermes)**. It uses the
  `reactnativedirect` debugger type, which is the one that works with the Hermes
  JavaScript engine. The older `reactnative` type doesn't work with this app.

To debug:

1. Open the repo root in VS Code. In a terminal, run `cd mobile`, then
   `npx expo start --dev-client`.
2. Press `a` in that terminal. Expo opens the app on the connected phone and
   sets up USB port forwarding.
3. Press F5 with **Attach to OpenSousVide (Hermes)** selected. Breakpoints in
   `App.tsx` and `src/` then stop the app.

Notes:

- The configuration attaches to Metro on port 8081. If Metro runs on another
  port, change `port` in `launch.json` to match.
- Make sure `adb` is on your `PATH` (the `platform-tools` folder of the Android
  SDK).
- The extension writes generated files to `.vscode/.react/`, which is
  gitignored.
- Without VS Code, press `j` in the Metro terminal to open React Native DevTools,
  which has a console, breakpoints, network inspector and component inspector.
  If VS Code fails to attach, close DevTools first, in case only one debugger
  can be connected at a time.

## Signed release APK

Release builds are signed with your own key. `plugins/withReleaseSigning.js`
reads it from these Gradle properties, normally in
`%USERPROFILE%\.gradle\gradle.properties` (or `~/.gradle/gradle.properties`)
so the passwords stay out of the repo:

```properties
OPENSOUSVIDE_UPLOAD_STORE_FILE=C:/path/to/your.keystore
OPENSOUSVIDE_UPLOAD_STORE_PASSWORD=...
OPENSOUSVIDE_UPLOAD_KEY_ALIAS=...
OPENSOUSVIDE_UPLOAD_KEY_PASSWORD=...
```

Use forward slashes in the path. If these are missing, the release build fails
at the signing step. It never falls back to the public debug key.

To build, run this from `mobile/android` (after `npx expo prebuild --platform android` if `android/` is missing):

```sh
./gradlew app:assembleRelease -PreactNativeArchitectures=armeabi-v7a,arm64-v8a
```

The APK is written to `android/app/build/outputs/apk/release/app-release.apk`.
It contains the JavaScript bundle, so it runs without Metro. Install it with
`adb install`, or copy it to a phone that allows installing unknown apps.

- **Keep the key.** Every update has to be signed with the same key. If the key
  changes, people must uninstall the app (losing their pairing) before they can
  install the new version.
- **Bump the version.** Raise `android.versionCode` in `app.json` for each APK
  you hand out, or Android will refuse to install it over an older one.
- **Remove the development build first.** A phone that has it installed can't
  install the release APK over it, because they're signed with different keys.

## Protobuf code

`src/proto/base_pb.ts` is generated from the shared `../proto/base.proto` by
`npm run proto` (uses `buf` and `protoc-gen-es`).

## Layout

- `App.tsx`: loads settings and shows the pairing or control screen. It
  connects only while the app is in the foreground.
- `src/joule/protocol.ts`: UUIDs, advertisement parsing, stream handles, and
  message encoding. No I/O. A port of `python/joule/protocol.py`.
- `src/joule/client.ts`: `JouleClient` (pair, authenticate, set temperature,
  stop, live feed) over a pluggable `Transport`. A port of
  `python/joule/client.py`.
- `src/joule/ble.ts`: permissions, scanning, and the BLE transport, built on
  `react-native-ble-manager`.
- `src/session.ts`: connection lifecycle (find, connect, authenticate,
  reconnect) and live status for the UI.
- `src/pairing.ts`: first-time pairing.
- `src/settings.ts`: the pairing key and preferences, stored with `expo-secure-store`.
- `src/ui/`: screens and theme.
